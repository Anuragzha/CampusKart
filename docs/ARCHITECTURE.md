## 4. State Management Strategy (Riverpod 2.5)

| Provider Type                | Used For                        | Example                                           |
| ---------------------------- | ------------------------------- | ------------------------------------------------- |
| `StreamProvider.autoDispose` | Real-time Firestore streams     | `listingsStreamProvider`, `chatStreamProvider`    |
| `AsyncNotifierProvider`      | AI API calls with loading/error | `aiDescriptionProvider`                           |
| `StateProvider`              | Local UI state                  | `selectedCategoryProvider`, `searchQueryProvider` |
| `Provider`                   | Derived/computed state          | `visibleListingsProvider`                         |

## 7. FastAPI AI Endpoints

### POST `/api/v1/ai/generate-description`

- **Input**: `{ item_title, category, condition, price, additional_notes? }`
- **Output**: `{ enhanced_title, generated_description, suggested_tags[] }`

### POST `/api/v1/ai/smart-replies`

- **Input**: `{ last_message, item_title, item_price, is_seller }`
- **Output**: `{ suggestions: [string, string, string] }`

### GET `/health`

- **Output**: `{ status: "ok", service: "campuskart-ai" }`

## 8. Key Architectural Decisions

1. **No payment gateway** — all transactions are physical (cash/UPI in person)
2. **AI is optional** — listings work without AI
3. **Client-side image compression** — max 1280px, ≤ 300 KB via `flutter_image_compress`
4. **Offline-first chat** — Firestore offline persistence
5. **Pagination** — 20 listings/page to manage Firestore quotas
6. **Auth redirect** — go_router redirect guard checks Firebase auth state
